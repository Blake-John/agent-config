算法哲学是一种计算美学运动，通过代码来表达。输出的文件包括 .md 文件（哲学）、.html 文件（交互式查看器）和 .js 文件（生成算法）。

这分两步进行：
1. 创建算法哲学（.md 文件）
2. 通过创建 p5.js 生成艺术来表现（.html + .js 文件）

首先，执行以下任务：

## 创建算法哲学

首先，创建一个**算法哲学**（而非静态图像或模板），通过以下方式诠释：
- 计算过程、涌现行为、数学之美
- 种子随机性、噪声场、有机系统
- 粒子、流动、场、力
- 参数化变化与受控混沌

### 关键理解
- **接收的是什么**：用户提供的一些微妙输入或指令作为参考，但仅作为基础；不应限制创作自由。
- **创建的是什么**：一种算法哲学/生成美学运动。
- **接下来做什么**：同一轮对话接收哲学并以代码表现——创建 p5.js 草图，其中 90% 是算法生成，10% 是核心参数。

考虑这种方法：
- 为生成艺术运动撰写宣言
- 下一阶段涉及编写让哲学活起来的算法

哲学必须强调：算法表达、涌现行为、计算之美、种子变化。

### 如何生成算法哲学

**命名运动**（1-2 个词）："有机湍流" / "量子和声" / "涌现的寂静"

**阐述哲学**（4-6 段——简洁但完整）：

要捕捉算法的精髓，表达这种哲学如何通过以下方式展现：
- 计算过程和数学关系？
- 噪声函数和随机性模式？
- 粒子行为和场动力学？
- 时间演化和系统状态？
- 参数化变化和涌现复杂性？

**关键指导原则：**
- **避免冗余**：每个算法方面应只提及一次。避免重复讨论噪声理论、粒子动力学或数学原理，除非是增添新的深度。
- **反复强调工艺水平**：哲学必须多次强调最终算法应看上去花费了无数小时的开发、经过精心打磨、出自该领域顶尖专家之手。这种框架至关重要——重复使用诸如"精心打造的算法"、"深厚计算专业知识的结晶"、"精益求精的优化"、"大师级的实现"等措辞。
- **留下创作空间**：明确算法方向，但要足够简洁，让下一个 Claude 有空间在极高的工艺水平上做出诠释性的实现选择。

哲学必须指导下一个版本以**算法方式**表达思想，而非通过静态图像。美存在于过程之中，而非最终画面。

### 哲学示例

**"有机湍流"**
哲学：受自然法则约束的混沌，从无序中涌现的秩序。
算法表达：由多层 Perlin 噪声驱动的流场。数千个粒子跟随矢量力，它们的轨迹累积成有机密度图。多噪声八度音阶创造湍流区和平静区。颜色从速度和密度中涌现——快速粒子燃烧明亮，慢速粒子淡入阴影。算法运行直至平衡——一个经过精心调校的平衡，每一个参数都由计算美学大师通过无数次迭代优化而成。

**"量子和声"**
哲学：离散实体表现出波动干涉模式。
算法表达：在网格上初始化的粒子，每个携带一个通过正弦波演化的相位值。当粒子靠近时，它们的相位产生干涉——相长干涉产生亮节点，相消干涉产生空洞。简谐运动生成复杂的涌现曼陀罗。这是通过精密的频率校准，每个比例都经过精心选择以产生共振之美。

**"递归低语"**
哲学：跨尺度的自相似性，有限空间中的无限深度。
算法表达：递归细分的分支结构。每个分支略有随机化，但受黄金比例约束。L-system 或递归细分生成既数学又有机的树状形态。微妙的噪声扰动打破完美对称。线条宽度随递归层级递减。每个分支角度都是深度数学探索的结晶。

**"场动力学"**
哲学：通过物质上的效应展现不可见的力量。
算法表达：由数学函数或噪声构建的矢量场。粒子在边缘生成，沿场线流动，在达到平衡或边界时消失。多个场可以吸引、排斥或旋转粒子。可视化仅显示痕迹——不可见力量的幽灵般证据。一个通过力平衡精心编排的计算之舞。

**"随机结晶"**
哲学：随机过程结晶成有序结构。
算法表达：随机圆填充或 Voronoi 镶嵌。从随机点开始，通过松弛算法让它们演化。细胞相互推开直至平衡。基于细胞大小、邻居数量或距中心距离着色。涌现的有机铺砌既随机又不可避免。每个种子都产生独特的晶体之美——大师级生成算法的标志。

*这些是精简示例。实际的算法哲学应为 4-6 个完整的段落。*

### 核心原则
- **算法哲学**：创建通过代码表达的计算世界观
- **过程重于结果**：始终强调美源于算法的执行过程——每次运行都是独特的
- **参数化表达**：思想通过数学关系、力、行为传达——而非静态构图
- **创作自由**：下一个 Claude 以算法方式诠释哲学——提供创作实现空间
- **纯粹生成艺术**：这是关于创造**活的算法**，而非带有随机性的静态图像
- **专家级工艺**：反复强调最终算法必须感觉是精心打造的、经过无数次迭代优化的、由计算美学领域顶尖专家的深厚专业知识结晶而成

**算法哲学应为 4-6 段长度。** 用充满诗意的计算哲学填充它，将预期愿景融合在一起。避免重复相同观点。将此算法哲学输出为 .md 文件。

### 技术要求

**种子随机性（Art Blocks 模式）：**
```javascript
// 始终使用种子以确保可重现性
let seed = 12345; // 或来自用户输入的 hash
randomSeed(seed);
noiseSeed(seed);
```

**参数结构——遵循哲学：**

要建立从算法哲学中自然涌现的参数，考虑："这个系统的哪些属性可以调节？"

```javascript
let params = {
  seed: 12345,  // 始终包含 seed 以确保可重现性
  // colors
  // 添加控制你的算法的参数：
  // - 数量（多少个？）
  // - 规模（多大？多快？）
  // - 概率（多可能？）
  // - 比例（什么比例？）
  // - 角度（什么方向？）
  // - 阈值（行为何时改变？）
};
```

**设计有效参数时，关注系统需要可调优的属性，而不是思考"模式类型"。**

**核心算法——表达哲学**：

**关键**：算法哲学应决定构建什么。

要通过代码表达哲学，避免思考"我应该使用哪种模式？"，而是思考"如何通过代码表达这种哲学？"

如果哲学是关于**有机涌现**，考虑使用：
- 随时间累积或生长的元素
- 受自然规则约束的随机过程
- 反馈循环和交互

如果哲学是关于**数学之美**，考虑使用：
- 几何关系和比例
- 三角函数和谐波
- 精确计算创造意外模式

如果哲学是关于**受控混沌**，考虑使用：
- 在严格边界内的随机变化
- 分叉和相变
- 从无序中涌现的秩序

**算法源自哲学，而非选项菜单。**

指导实现时，让概念本质启发创造性和原创性的选择。构建能表达该特定请求愿景的作品。

**Canvas 设置**：标准 p5.js 结构：
```javascript
function setup() {
  createCanvas(1200, 1200);
  // 初始化你的系统
}

function draw() {
  // 你的生成算法
  // 可以是静态的（noLoop）或动画的
}
```

### 工艺要求

**关键**：要达到大师级水平，创建的算法必须感觉像是由大师级生成艺术家历经无数次迭代打磨而成。精心调优每个参数。确保每个模式都有目的地涌现。这不是随机噪声——这是通过深厚专业知识打磨的**受控混沌**。

- **平衡**：复杂度而不杂乱，有序而不僵化
- **色彩和谐**：经过深思熟虑的调色板，而非随机的 RGB 值
- **构图**：即使在随机性中，也保持视觉层次和流动
- **性能**：流畅执行，如为动画则针对实时优化
- **可重现性**：相同种子始终产生完全相同的输出

### 输出格式

输出：
1. **算法哲学**——作为 markdown 或文本解释生成美学
2. **单个 HTML 作品**——基于 `templates/viewer.html` 构建的自包含交互式生成艺术（见步骤 0 和下一节）

HTML 作品包含一切：p5.js（从 CDN 加载）、算法、参数控制和 UI——全部在一个文件中，可在 claude.ai 作品展示或任何浏览器中立即运行。从模板文件开始，而非从头创建。

## 交互式作品创建

**提醒：** 应该已经阅读了 `templates/viewer.html`（见步骤 0）。以该文件为起点。

为了允许探索生成艺术，创建一个单独的、自包含的 HTML 作品。确保该作品在 claude.ai 或任何浏览器中立即运行——无需设置。所有内容内联嵌入。

### 关键：固定部分 vs 可变部分

`templates/viewer.html` 文件是基础。它包含所需的确切结构和样式。

**固定部分（始终按所示包含）：**
- 布局结构（头部、侧边栏、主 canvas 区域）
- Anthropic 品牌风格（UI 颜色、字体、渐变）
- 侧边栏中的种子部分：
  - 种子显示
  - 上一个/下一个按钮
  - 随机按钮
  - 跳转到种子输入框 + 跳转按钮
- 侧边栏中的操作部分：
  - 重新生成按钮
  - 重置按钮

**可变部分（为每个作品自定义）：**
- 整个 p5.js 算法（setup/draw/classes）
- 参数对象（定义艺术需要的参数）
- 侧边栏中的参数部分：
  - 参数控制数量
  - 参数名称
  - 滑块的 min/max/step 值
  - 控制类型（滑块、输入框等）
- 颜色部分（可选）：
  - 有些艺术需要颜色选择器
  - 有些艺术可能使用固定颜色
  - 有些艺术可能是单色的（不需要颜色控制）
  - 根据艺术需求决定

**每个作品应有独特的参数和算法！** 固定部分提供一致的 UX——其余一切表达独特的愿景。

### 必需功能

**1. 参数控制**
- 数值参数的滑块（粒子数量、噪声尺度、速度等）
- 调色板的颜色选择器
- 参数变化时的实时更新
- 重置按钮恢复默认值

**2. 种子导航**
- 显示当前种子编号
- "上一个"和"下一个"按钮循环切换种子
- "随机"按钮生成随机种子
- 输入字段跳转到特定种子
- 请求时生成 100 个变体（种子 1-100）

**3. 单作品结构**
```html
<!DOCTYPE html>
<html>
<head>
  <!-- p5.js from CDN - always available -->
  <script src="https://cdnjs.cloudflare.com/ajax/libs/p5.js/1.7.0/p5.min.js"></script>
  <style>
    /* 所有样式内联——简洁、极简 */
    /* Canvas 在上方，控制在下方 */
  </style>
</head>
<body>
  <div id="canvas-container"></div>
  <div id="controls">
    <!-- 所有参数控制 -->
  </div>
  <script>
    // 所有 p5.js 代码在此内联
    // 参数对象、类、函数
    // setup() 和 draw()
    // UI 事件处理
    // 一切自包含
  </script>
</body>
</html>
```

**关键**：这是一个单独的作品。无外部文件，无导入（除了 p5.js CDN）。所有内容内联。

**4. 实现细节——构建侧边栏**

侧边栏结构：

**1. 种子（固定）**——始终按所示包含：
- 种子显示
- 上一个/下一个/随机/跳转按钮

**2. 参数（可变）**——为作品创建控制：
```html
<div class="control-group">
    <label>参数名称</label>
    <input type="range" id="param" min="..." max="..." step="..." value="..." oninput="updateParam('param', this.value)">
    <span class="value-display" id="param-value">...</span>
</div>
```
根据需要添加尽可能多的 control-group div。

**3. 颜色（可选/可变）**——如果艺术需要可调颜色则包含：
- 如果用户应控制调色板，则添加颜色选择器
- 如果艺术使用固定颜色，则跳过此部分
- 如果艺术是单色的，则跳过

**4. 操作（固定）**——始终按所示包含：
- 重新生成按钮
- 重置按钮
- 下载 PNG 按钮

**要求**：
- 种子控制必须工作（上一个/下一个/随机/跳转/显示）
- 所有参数必须有 UI 控制
- 重新生成、重置、下载按钮必须工作
- 保留 Anthropic 品牌风格（UI 样式，而非艺术颜色）

### 使用作品

HTML 作品立即可用：
1. **在 claude.ai 中**：显示为交互式作品——立即运行
2. **作为文件**：保存并在任何浏览器中打开——无需服务器
3. **分享**：发送 HTML 文件——完全自包含

## 变体与探索

作品默认包含种子导航（上一个/下一个/随机按钮），允许用户探索各种变体而无需创建多个文件。如果用户希望突出显示特定变体：

这就像从同一印版制作一系列版画——算法是一致的，但每个种子揭示了其潜力的不同侧面。交互式特性意味着用户通过探索种子空间发现自己的最爱。

## 创作过程

**用户请求** → **算法哲学** → **实现**

每个请求都是独特的。过程涉及：

1. **解读用户的意图**——寻求什么样的美学？
2. **创建算法哲学**（4-6 段）描述计算方法
3. **用代码实现**——构建表达此哲学的算法
4. **设计合适的参数**——什么应该是可调优的？
5. **构建匹配的 UI 控制**——这些参数的滑块/输入框

**常量**：
- Anthropic 品牌风格（颜色、字体、布局）
- 种子导航（始终存在）
- 自包含 HTML 作品

**其他一切均为变量**：
- 算法本身
- 参数
- UI 控制
- 视觉输出

为达到最佳效果，相信创造力，让哲学指导实现。
